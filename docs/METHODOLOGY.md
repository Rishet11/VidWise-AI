# VidWise: A High-Integrity Evaluation Methodology for Multi-Video Research and Citation Grounding

## 1. Introduction
In the race to build Retrieval-Augmented Generation (RAG) applications, the standard approach to evaluation has become alarmingly superficial. Teams routinely benchmark their systems using synthetic questions generated by LLMs, grade them using uncalibrated "LLM-as-a-judge" prompts, and publish final accuracy tables claiming flawless performance. These metrics often crumble under real-world usage, where transcript boundary issues, network latency, and citation mismatches make the system untrustworthy.

VidWise is built on a different premise: a RAG system is only as good as its worst citation. If a user clicks a citation chip to verify a claim and finds themselves dropped into a random segment of a YouTube video that has nothing to do with the text, the system has failed. To address this, we have developed a rigorous, reproducible evaluation harness under `benchmarks/`. 

**Status Disclosure**: The evaluation harness and runner are fully implemented. However, the human labels are currently undergoing a strict review protocol. We refuse to publish tentative accuracy percentages until the ground truth dataset is fully verified by human labelers. The methodology detailed below is the core engineering deliverable.

## 2. Evaluation Design Philosophy
A common pitfall in RAG evaluation is conflating retrieval failures with generation failures. When a system provides an incorrect or incomplete answer, did it fail because it searched the wrong documents (retrieval failure), or because it had the right information but synthesized it incorrectly (grounding/generation failure)?

To diagnose these distinct problems, VidWise explicitly separates retrieval quality from answer grounding:
* **Retrieval Quality**: We measure the system's ability to locate the exact second-level segments containing the answer. By assessing retrieval independently, we can tune chunking sizes, embedding models, and reranking parameters without being biased by the generator's behavior.
* **Answer Grounding**: We isolate the generation phase by verifying whether every atomic claim in the generated response is strictly supported by the retrieved context. A perfectly grounded system might fail to answer a question due to poor retrieval, but it will never state an unsupported claim.

By decoupling these two metrics, we gain immediate diagnostic clarity. We can pinpoint if a performance drop is due to our FAISS index layout or if `gemini-2.5-flash` is failing to adhere to the grounding constraints.

## 3. Label Protocol Details
To make evaluations reproducible, we must avoid evaluating against a moving target.
* **Frozen Corpus**: VidWise utilizes a frozen public-video corpus (a curated set of YC Startup School talks). This prevents external factors—such as a video being deleted or YouTube native captions updating—from invalidating past runs.
* **Segment-Level Labels**: Instead of labeling a whole document as "relevant," human annotators label specific, second-level start and end timestamps (e.g., `[Video A, 124s, 155s]`) where the concrete answer to the evaluation question is spoken.
* **Personal Verification Requirement**: Ground truth cannot be generated by an LLM or delegated to automated heuristic scripts. Every gold-standard label must be personally verified by a human annotator who has watched the segment to confirm the answer is actually present. If a question is a "negative question" (designed to test the system's ability to abstain when no answer is present), it is explicitly labeled as such, and the expected behavior is complete abstention.

## 4. Metric Design and Statistical Rigor
Rather than relying on simple point-estimate averages, VidWise introduces statistical confidence intervals and variance reporting:
* **Wilson Score Intervals**: Every rate metric (such as retrieval recall rate or grounded claim precision) is reported with a Wilson score interval. This represents the statistical confidence of the measurement given the sample size, preventing small sample sizes from masquerading as definitive results.
* **Three-Run Variance**: LLM APIs are inherently non-deterministic, and network conditions fluctuate. The VidWise evaluation runner executes each configuration across three repeated runs. This exposes variance in latency, token consumption, and response consistency.
* **Ablation Configurations**: To measure the exact value added by each step in our retrieval pipeline, the runner supports ablation configurations. We run and compare:
  1. *Baseline (`naive`)*: Dense retrieval over the `BAAI/bge-base-en-v1.5` index using the raw user query.
  2. *Query Expansion Only (`multi_query`)*: Plain-Python multi-query generation before vector search.
  3. *Reranking Only (`rerank`)*: Dense retrieval followed by the local cross-encoder reranker (`cross-encoder/ms-marco-MiniLM-L-6-v2`, default) or the LLM listwise reranker (`rerank_mode="llm"`).
  4. *Full Pipeline (`combined`)*: Both multi-query expansion and reranking enabled.
  5. *HyDE (`hyde`)*: Retrieves against an LLM-generated hypothetical answer passage instead of the raw query, targeting abstract/synthesis questions. Eval-only; not enabled in the live app.

## 5. LLM-Judge Validity and Limits
While manual evaluation is the gold standard, it is time-consuming. VidWise utilizes an LLM judge to accelerate the analysis of answer grounding. However, we treat the LLM judge with healthy skepticism:
* **Assists, Never Defines**: The LLM judge is used strictly to flag potential grounding violations or citation errors for human review. It never overrides or defines the final ground-truth accuracy metrics.
* **Agreement Reporting**: The runner tracks and reports the agreement rate (such as Cohen's Kappa or raw overlap percentage) between the LLM judge's assessments and the human-labeled ground truth. If the LLM judge's false negative or false positive rate rises, it indicates the judge prompt is drift-prone and must be tuned, rather than assuming the LLM judge is correct.

## 6. Inter-Labeler Reliability Design
To eliminate subjective bias in the evaluation set, VidWise defines a formal inter-labeler reliability protocol:
* **Dual-Labeler Subsampling**: A second independent human labeler annotates a random subset of at least ten questions.
* **Cohen's Kappa Calculation**: We compute Cohen's Kappa on the overlap of the identified target segments and grounding judgments. 
* **Adjudication Protocol**: Any case of disagreement (Kappa < 0.8) triggers a structured adjudication session. The labelers review the conflicting segment together, define the source of ambiguity, and update the labeling guidelines to refine the protocol.

## 7. Failure Taxonomy Approach
Grouping every error under the generic umbrella of "hallucination" is unhelpful for engineering iteration. VidWise classifies errors into a specific failure taxonomy:
* **Caption Boundary Drift**: The true answer is split across transcript chunk boundaries, leaving the retrieved snippet without sufficient context for the generator.
* **Reranker Displacement**: The reranker (local cross-encoder by default, or the LLM listwise reranker in `rerank_mode="llm"`) incorrectly pushes the relevant chunk below the retrieval cutoff (K=4), resulting in a failure to answer.
* **Synthesis Omission**: Retrieval succeeds, and the correct chunks are placed in the context window, but the LLM fails to synthesize the points in the final summary.
* **Attribution Mismatch**: The generated claim is factually correct, but the citation chip points to the wrong video or timestamp.

## 8. Honest Framing
By design, the VidWise benchmark runner fails closed. If a developer attempts to execute the runner while the evaluation set has rows marked as `needs_rishet_review`, the runner halts and refuses to compile results. This enforces our commitment to integrity: we do not present metrics until they are fully backed by a completed human label set and a reproducible run artifact. We believe that an honest, well-documented methodology is infinitely more valuable than fabricated performance claims.
